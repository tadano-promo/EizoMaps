# パスワードの決まり（鍵付きページ・限定公開のスケジュールなど）

2026-10-31 翠くん：「今後同じことがあった場合を想定すると毎回パスワードが変わり過ぎるのもなので　…そんな作業があってもクリエイターが任意で変えない限りは変わらない仕組みにしておく」

## 決まり
1. **クリエイターが自分で変えない限り、パスワードは変わらない。** アップデート・運営の作業・不具合の直しで、本人に設定し直しをお願いすることはしない。
2. 鍵付きページ（stock_pages）は、データベースがこれを守る（038）。`password_hash` は `set_stock_page_password`（本人の関数）を通したときしか書き換えられない。ほかの SQL で書き換えようとすると止まる。
3. 保存の形を変えるとき（鍵の入れ替え・暗号の方式の変更など）は、`password_enc` を「今のパスワードに戻して → 新しい形で入れ直す」。パスワード自体は変えない。前に渡した相手もそのまま開ける状態を保つ。
4. 新しくパスワードを使う機能を作るときは、最初から「元に戻せる形（本人にだけ見せる）」と「確認用の形」の2つで持ち、あとから設定し直しが要らないようにする。

## 例外（2026-10-31 の1回だけ）
037 で「本人が見る」機能を入れたとき、それより前に設定したパスワードは元に戻せない形だけで保存していたため、設定し直しをお願いした（kaz さん・伊藤さんの2ページ）。同じパスワードを入れ直せば、前に渡した相手もそのまま開ける。これからは行わない。
